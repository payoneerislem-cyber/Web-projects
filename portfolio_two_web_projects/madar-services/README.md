# MADAR Services — Business Website Demo

A standalone bilingual Arabic/English Flask website for a fictional home and commercial-space services brand. It is designed as a portfolio-ready demonstration, not as a claim that MADAR is a real operating business.

## What is included

- Responsive landing page with service catalog, process, values, FAQ, and clear quote-request CTA.
- A starter privacy notice at `/privacy` and a `robots.txt` that keeps the admin path out of crawlers.
- Arabic/English language switch and RTL/LTR layout support.
- Validated service request form with consent, optional date/email, input length limits, CSRF protection, honeypot field, and field-level validation.
- Private admin panel with session login, sample records clearly marked `DEMO`, request status updates, and basic request totals.
- SQLite for local work and PostgreSQL support for hosting.
- Optional SMTP notifications to the administrator and an acknowledgement to the requester; the form still stores requests if SMTP is not configured.
- Health endpoint, security headers, environment configuration, deployment example, and basic smoke tests.

## Run on Windows

1. Extract the ZIP into a normal folder.
2. Open that folder in VS Code.
3. Double-click `run_windows.bat` (on first run it creates and opens `.env` so you can review the settings), or run the commands below in the VS Code terminal:

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
python app.py
```

Open `http://127.0.0.1:5000`.

Before using the admin panel locally, edit `.env` and set `ADMIN_PASSWORD` and `SECRET_KEY` to your own values. The sample local admin password shown by the example file is only a placeholder; never reuse it online.

## Admin panel

- URL: `/admin/login`
- Password: the value of `ADMIN_PASSWORD` in `.env`
- The application does not expose a public registration route.
- Seed records are fictional, use `DEMO` tags, and can be disabled with `SEED_DEMO_DATA=false`.

## Deployment

The included `render.yaml` creates a Render web service but asks you to provide `ADMIN_PASSWORD` and `DATABASE_URL`. Use a durable PostgreSQL database URL (for PostgreSQL, the application normalizes `postgres://`/`postgresql://` to the `psycopg` driver). `SECRET_KEY` is generated by Render. The app intentionally fails startup on Render if its database URL or admin password is missing instead of silently writing customer data to an ephemeral SQLite file.

**Important:** Render's free web service filesystem is ephemeral, and Render's free PostgreSQL databases currently expire after 30 days. Those options are suitable for a temporary portfolio demo only. Before accepting real customer enquiries, attach a durable database with an appropriate backup plan, change `SEED_DEMO_DATA=false`, set a strong unique admin password, replace all demo business/contact details, and publish a privacy policy. See the current platform docs: https://render.com/docs/free and https://render.com/docs/postgresql.

Set `BUSINESS_NAME_AR`, `BUSINESS_NAME_EN`, `PUBLIC_PHONE`, `PUBLIC_EMAIL`, and `PUBLIC_CITY` for the actual business. The included privacy notice is a starting template and must be adapted and legally reviewed. The `.example.test` email address is deliberately non-deliverable. Set the `MAIL_*` values if administrator email notifications are required.

## Environment variables

| Variable | Purpose |
|---|---|
| `SECRET_KEY` | Flask session/CSRF secret. Use a long random value. |
| `ADMIN_PASSWORD` | Admin login password. Use a unique strong value. |
| `DATABASE_URL` | PostgreSQL URL in production; omitted locally to use SQLite. |
| `DATABASE_PATH` | Optional local SQLite file path. |
| `SEED_DEMO_DATA` | Defaults to `true`; set to `false` to stop inserting sample enquiries. |
| `BUSINESS_NAME_AR`, `BUSINESS_NAME_EN`, `PUBLIC_PHONE`, `PUBLIC_EMAIL`, `PUBLIC_CITY` | Public identity/contact fields. |
| `MAIL_SERVER`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_DEFAULT_SENDER`, `MAIL_TO` | Optional SMTP notifications. |
| `COOKIE_SECURE` | Set `true` when serving over HTTPS. |
| `BUSINESS_TIMEZONE` | Defaults to `Africa/Algiers`; controls date comparisons and timestamps. |

## Before using with real customers

Change the brand, service coverage and contact details; create a persistent PostgreSQL database and backup plan; disable demo records; use a unique strong secret and admin password; configure and test email; add a real privacy notice and business terms; verify applicable local legal requirements; and test the live deployment with a non-sensitive sample enquiry. This starter stores enquiry details but does not include payment processing or an external CRM integration.
